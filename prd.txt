I analyzed the roadmap end-to-end. The document is not merely a list of technologies: it defines a **career progression system** from Data Analyst → Strong Data Analyst → Analytics Engineering → Analytics Engineer, with explicit phases, milestones, projects, continuous business-thinking/communication/AI practices, and the rule **“Learn → Build → Apply → Improve → Apply again.”**  

The biggest mistake would be building a generic “course checklist.” That would completely miss the roadmap. The tracker needs to behave like a **career operating system**: learning progress + competency + evidence + projects + revision + job-readiness + application progress.

Below is the PRD I would give to an AI product/UI builder.

# LEARNING PROGRESS TRACKER

## Data Analyst → Analytics Engineer Career Operating System

**Document Type:** Product Requirements Document
**Product:** Personal Learning Progress & Career Tracker
**Primary Roadmap:** Data Analyst → Analytics Engineer
**Design Standard:** Premium SaaS / Professional Developer Tool
**Platforms:** Responsive Web Application
**Modes:** Light + Dark
**Primary Objective:** Convert the supplied 19-phase learning roadmap into a measurable, evidence-driven career progression system.

---

# 1. PRODUCT VISION

Build a premium learning tracker that transforms the Data Analyst → Analytics Engineer roadmap into an interactive progression system.

The product must NOT feel like:

* a basic checklist
* a Notion template
* a generic habit tracker
* a gamified children's learning app
* a course marketplace
* a simple progress bar

It should feel like a combination of:

* Linear
* GitHub
* modern developer dashboards
* premium SaaS analytics products
* professional project-management software
* competency tracking systems

The core mental model is:

> **Learn → Practice → Demonstrate → Validate → Build → Apply → Improve → Repeat**

The application must measure not only whether a topic was “completed,” but whether the learner has produced enough evidence to reasonably claim competency.

# 95. FINAL DESIGN DIRECTION

The finished product should visually communicate:

> **“This is the control center for becoming an Analytics Engineer.”**

Not:

> “This is a checklist for watching courses.”

The learner should open the dashboard and immediately understand:

**Where I am → What I know → What I can prove → What I should do next → What I need for the next career milestone.**

The entire experience should be structured around the roadmap's central philosophy:

> **Learn → Build → Apply → Improve → Apply again.**

The application should therefore function simultaneously as:

**Learning Tracker + Competency Matrix + Portfolio Manager + Project Tracker + Review System + Career Readiness Dashboard + Job Application Tracker.**

That is the product.

The critical architectural decision here is the separation of **progress, competency, evidence, and career readiness**. If the AI builder collapses those into one percentage, the resulting product will look polished but will be fundamentally useless.

The roadmap itself already gives you the career architecture; the tracker should add the **measurement and execution layer** without rewriting that architecture.
